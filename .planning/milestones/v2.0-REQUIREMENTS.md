# Requirements: Pi Web — Enhanced Orchestration

**Defined:** 2026-10-15
**Core Value:** Agent sessions execute with the same safety rules and orchestration enforcement as the CLI

## v2 Requirements

Requirements for this milestone. Each maps to roadmap phases.

### PID Resilience

- [x] **PID-01**: Lock schema v2 writes `{pid, proc_start, boot_id, instance_nonce, heartbeat_seq, heartbeat_at, state, last_error}` atomically via `os.replace`
- [x] **PID-02**: Python-side `verify_identity()` helper validates PID + proc_start match before any signal
- [x] **PID-03**: Pre-v2 lock files report `unverified` status (backward compatibility)
- [x] **PID-04**: Heartbeat advances from the work loop, not a separate thread

### Lane Driver Status UI

- [x] **UI-01**: Read-only Next.js API route returns daemon snapshot DTO with `force-dynamic` + `no-store`
- [x] **UI-02**: Parse failures return `unknown` status, distinct from `stopped`
- [x] **UI-03**: React status badge uses discriminated union (`running | stopped | errored | stale | unknown`) with heartbeat age
- [x] **UI-04**: Client uses single-flight `setTimeout` polling (5s visible, paused hidden, backoff on errors)

### Block Rule Telemetry

- [x] **TEL-01**: Per-session collector decorates rules at registration with timing and block counts
- [x] **TEL-02**: Only invoked rules are counted; short-circuited rules excluded
- [x] **TEL-03**: Snapshots written atomically and debounced; API reads them
- [x] **TEL-04**: Telemetry failures never change authorization decisions
- [x] **TEL-05**: No raw tool arguments, command strings, or absolute paths in telemetry output

### Async Block Rules

- [x] **ASYNC-01**: `evaluateBlockRulesAsync` prefetches git facts asynchronously into frozen context, then runs rules sync
- [x] **ASYNC-02**: Sync `evaluateBlockRules` unchanged; throws if a rule returns a thenable
- [x] **ASYNC-03**: Async git queries use promisified `execFile` with AbortSignal, timeout, windowsHide, no shell
- [x] **ASYNC-04**: Per-rule timeout with explicit fail-closed/fail-open policy

### Testing

- [x] **TEST-01**: Each new module has co-located `.test.mjs` with edge cases
- [x] **TEST-02**: Lock schema v2 tested with pre-v2 lock files, stale PIDs, identity mismatch
- [x] **TEST-03**: Telemetry tested with concurrent sessions, snapshot isolation

## Out of Scope

| Feature | Reason |
|---------|--------|
| Start/stop daemon buttons in UI | Anti-feature without auth/CSRF protection (research consensus) |
| WebSocket/SSE for status updates | Polling is sufficient for daemon heartbeats (research consensus) |
| OpenTelemetry SDK | Too heavy; decorator pattern with fixed-bucket histograms suffices |
| Cross-platform Node.js PID probing | Python-first rule — Python owns process identity |
| Async rule evaluation with concurrent execution | Sequential avoids unnecessary git subprocesses after early block |
